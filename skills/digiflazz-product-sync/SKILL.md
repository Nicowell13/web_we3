# Digiflazz Product Sync

Use this procedure when Digiflazz product import returns zero products, `data: null`, HTTP 500, or admin sync failures.

1. Inspect the active supplier factory, Digiflazz adapter, product-sync service, current database columns, and backend logs; confirm the failing layer before changing code.
2. Confirm only credential presence and length from loaded environment files; never print usernames, API keys, signatures, or request bodies containing them.
3. Call `/v1/price-list` once with `cmd: "prepaid"`, configured username, and MD5 of `username + apiKey + "pricelist"`; omit `code` when requesting the full catalog, then verify HTTP status and array count without logging product data or secrets. Never use `/v1/transaction` to probe product sync because it creates or checks an order rather than returning the catalog.
4. Treat a non-2xx response or non-array price-list payload as an explicit error; propagate the provider message through the admin API and render that message in the UI instead of a generic failure. Disable the sync control while its request is active and render returned `created`, `updated`, `unchanged`, `failed`, and `total` counts on success; do not convert malformed responses to an empty product list.
5. Compare Drizzle schema with live PostgreSQL `information_schema` when admin endpoints also return HTTP 500; generate and inspect an additive migration, then apply it only after confirming it preserves existing tables and data.
6. Run product sync once after the direct price-list probe succeeds; classify each supplier item from `brand`, `type`, and product text into stable catalog categories (`Game`, `Pulsa`, `Data`, `PLN`, `E-Wallet`, `Voucher`, or `Other`) by checking data/quota/internet/gb keywords to split phone provider products into distinct catalog entries (`[brand]` under `Pulsa` vs `[brand]-data` named `[brand] Data` under `Data`). Derive each mapped product's catalog key from the classifier's group name rather than raw supplier `game_id` or brand, because one raw operator key otherwise merges both groups and later items overwrite the parent category. Resync existing rows after this correction, then audit only available operator products and require zero keyword/category mismatches. Ensure public and admin product APIs return `productType`, `brand`, category, and group name; make admin group chips filter by classified group name and make public UI tabs mutually exclusive. If the local game catalog is empty or lacks a supplier brand, normalize that brand into a canonical slug, reuse existing rows by normalized id/name to avoid casing or spacing duplicates, create the required game row with a safe local placeholder image, then insert its products; update existing game rows with the classified category and improved group name on later syncs. Prefer product-name/type game hints over a closed brand allowlist, add each newly observed game pattern to the classifier test, and repair existing catalog rows by game slug during the same sync. Map inactive Digiflazz products (`buyer_product_status` or `seller_product_status` is false, or status is non-normal) to `off` rather than `unavailable`, reconcile products absent from the supplier payload by setting `supplierStatus: 'deleted'` and `isActive: false`, and ensure the admin UI filters out `off` and `deleted` products by default so operators do not waste time verifying dead stock. Recompute `sellPrice` from configured `marginType` and `marginValue` when `basePrice` updates during sync, otherwise preserve existing pricing; update supplier fields only; report `gamesCreated`, `groupsCreated`, `groupsUpdated`, `created`, `updated`, `unchanged`, `deleted`, `failed`, and `total`. Query live game/product/synced counts and category counts after the run; close the issue only when rows exist and categories are sensible. If Digiflazz reports a price-list rate limit, stop retrying and report the temporary blocker.
7. Before rerunning dev servers for browser verification, stop stale `next dev` and `server/index` processes, delete `.next`, remove `tsconfig.tsbuildinfo`, then start backend on `3001` and frontend on `3000`; if Next falls back to another port, stop the old port owner and restart Next.
8. For admin product review after classification, join the admin product list to `games_catalog` and return category/group fields without exposing public cost; render category tabs, dynamic group/provider chips, composed search/status filters, and preserve bulk actions and pricing controls.
9. Add an admin-only `/products/summary` endpoint when grouped UI needs counts; aggregate category/group totals, active totals, and latest `syncedAt` without returning `basePrice` or secrets, then use it for dashboard counts.
10. Audit paid-order fulfillment end to end before declaring checkout complete: load each transaction joined to its product so `supplierProductCode` cannot be empty; verify the DOKU webhook signature and paid amount; transition `PENDING` to `PAID`; call Digiflazz `/v1/transaction` with the selected supplier SKU, stable WETRI order ID as `ref_id`, and the supplier-required `customer_no` composition (append game zone/server ID when that product requires it); map immediate `Sukses`, `Gagal`, and `Pending` responses to `SUCCESS`, `FAILED`, and `PROCESSING`, persist supplier reference/SN, and leave paid supplier failures retryable with an audit record. Add regression tests that assert SKU, composed target, and immediate supplier status mapping; verify a reconciliation path exists for later pending completion. For PLN customer validation, call `/v1/inquiry-pln` with `username`, `customer_no`, and MD5 of `username + apiKey + customer_no`; parse the wrapped `data` object and accept only `status: "Sukses"`, `rc: "00"`, an exact returned `customer_no`, and a non-empty `name`. Return only a masked customer name plus needed meter/subscriber/power metadata; reject failed response codes, mismatched customer numbers, missing names, network errors, and unsupported suppliers. Never fabricate customer names or treat digit length as proof that a customer exists. Keep PLN inquiry public-safe by signing requests server-side with store credentials so unauthenticated clients never receive provider secrets or unmasked names. Prove inquiry credentials independently from balance credentials with one safe inquiry call: a successful `/cek-saldo` does not prove `/inquiry-pln` accepts the same environment/key pair. Trim loaded credential values, support a separately configured PLN username/key when provider environments require it, and classify signature/IP/provider failures as upstream-service errors (HTTP 502) rather than invalid customer IDs (HTTP 400); show clients a sanitized availability message while retaining exact provider diagnostics server-side. Cache successful inquiry results in memory with a short TTL (e.g., 5 minutes) to protect supplier rate limits; and re-verify PLN customer numbers server-side during payment link/order creation before issuing invoices. For game orders that carry zone/server ID, try Digiflazz target format A first by combining `user_id` + `zone_id`; if supplier rejects with a format/customer-number mismatch, retry once with format B using the split value path already supported by the adapter, and record which format won so later retries do not loop the same bad shape. Inject a supplier stub in tests to cover valid, cached, random-invalid, mismatched, and missing-name responses.
11. Implement recurring sync by extending the existing scheduler and server entrypoint rather than leaving standalone services unwired: start one central scheduler exactly once from the server listen callback, preserve existing scheduled work, run full price/product reconciliation every 4 hours, and run supplier availability reconciliation every hour. On recovery, update `supplierStatus` to `available` without automatically enabling a product an admin intentionally disabled; on supplier failure, set `supplierStatus` to `off` and deactivate it. Before paid fulfillment, compare latest stored supplier `basePrice` with the transaction's immutable `originalAmount`; when cost exceeds that ceiling, skip the supplier order, retain a retryable processing state, set `metadata.needsAdminAction`, and audit the hold. Otherwise pass that ceiling as Digiflazz `max_price` through the provider interface and adapter. Delete any duplicate validator service once this logic lives in the fulfillment path. Verify scheduler imports from the real module paths and every audit insert includes required `referenceId`, then run the complete test suite so server-import failures surface.
12. Verify `/api/health`, `/old-school`, and `/icon.png`, run `bun test` and `bun run build`, and commit only adapter, sync-service, migration, transaction, test, and admin UI files after `git status` confirms unrelated files remain unstaged.
